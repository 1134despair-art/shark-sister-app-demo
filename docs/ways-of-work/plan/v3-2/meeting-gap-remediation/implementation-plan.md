# 鲨鱼妹妹 App 会议差异整改计划

## 1. 文档目的

本文件用于追踪《物联二路1号 Word 未提及调整项》与当前 UniApp 工程之间的差异。它不是新增需求清单，只有会议中已经确认、且不与 V3.2 原始需求冲突的内容才进入实现。

验收基准：

- V3.2 原始需求表负责定义正式业务范围。
- 蓝白版 UI 图库负责定义视觉、页面结构和交互表现。
- 会议纪要只补充原需求未写清的规则，不据此扩展未确认模块。
- `U01-U09` 均保持待确认，不直接进入开发。

状态定义：

| 状态 | 含义 |
|---|---|
| `complete-local` | 页面、校验、关联数据、持久化和测试均可在本地闭环 |
| `in-remediation` | 已有基础实现，本轮继续补齐 |
| `integration-ready` | 前端接口和不可用状态可交付，正式能力依赖后台或硬件 |
| `blocked-external` | 必须依赖后台、硬件协议、法务文本或外部数据，不能伪造成功 |
| `needs-confirmation` | 会议未形成唯一结论，不实施 |
| `out-of-app-scope` | 明确属于后台或测试管理，不在 App 工程内实现 |

## 5. 实施顺序

### 批次 A：设备与数据安全

1. 修复连接状态文案和命令回读状态。
2. 增加 OTA 前置校验。
3. 解绑/重新绑定保留售后历史并隔离可见范围。
4. 增加设备身份映射和详情展示。

### 批次 B：入口与资料

1. 区分每次启动页和首次安装介绍页。
2. 项目 SN 支持搜索、扫描和手工输入。
3. FAQ 按设备类型/型号筛选并处理文件失效。
4. 增加本地隐私同意与定位权限记录。

### 批次 C：经销商闭环

1. 项目组合筛选。
2. 换件关系、库存和旧件处置。
3. 多项采购申请与费用快照。
4. 维修账单明细和售后责任历史。

## 6. 验收规则

- 任何成功提示必须对应已提交事务，不能用 Toast 代替数据操作。
- 关联操作同时验证页面状态、主实体、关联实体、时间线和审计事件。
- 外部能力未配置时返回明确不可用状态，不创建虚假连接、支付或升级记录。
- 游客、普通用户、二级经销商和员工的菜单、路由、数据与操作权限保持一致。
- 每项整改完成后更新本表状态，并附单元测试或 E2E 测试文件作为证据。

处理口径：

| 场景 | APP Demo 行为 | 持久化结果 |
|---|---|---|
| 跨区安装项目 | 提交后显示“待后台审核”，项目详情可执行后台通过/驳回演示 | 更新项目状态和跨区状态；通过后关联设备/登记记录；写入审批消息和审计 |
| 留言转总部 | 转单后显示总部待接收，进度页可依次执行后台接收、后台完成 | 更新留言转单、工单处理状态、归属标签、时间线、用户消息和审计 |

## 9. 客户追加语言范围（2026-08-25）

显示语言由原 V3.2 的中文/英文扩展为 13 种：中文、英文、韩语、日语、土耳其语、阿拉伯语、葡萄牙语、西班牙语、法语、德语、意大利语、荷兰语和俄语。

- `tests/locales.test.ts` 验证 13 种代码、唯一性、回退及 RTL；`tests/e2e/app.spec.ts` 验证语言列表、日语/阿拉伯语持久化和无横向溢出。
